# Database V2 — مرحلة التأسيس

## الحالة
فرع تطوير مستقل، وليس ترقية مباشرة للإنتاج. قاعدة الإصدار الحالي تخزن جميع مجموعات السجلات في JSONB مع رقم مراجعة؛ الموظفون ومساحات الحسابات الشخصية مرتبطون بواجهات RPC الحالية. لم تتغير واجهات RPC أو تطبيقات الهاتف.

## المرحلة المنفذة
- `001-shadow-schema.sql`: مخطط خاص باسم portfleet_v2، 12 جدول سجلات وجدول workspace. لكل سجل مفتاح مرتبط بمالك المساحة ومعرّف السجل القديم، وموضعه في المصفوفة الأصلية، وحقول ذات أنواع محددة، ونسخة JSONB أصلية لحفظ الحقول الأخرى دون إسقاطها.
- مفاتيح خارجية تمنع الربط بسجل في مساحة مالك آخر، وفهارس لاستعلامات الآليات والصيانة والوقود والمستودع وغيرها. قيد تفرد للأكواد مع توحيد الأرقام العربية والفارسية والمسافات وحالة الأحرف؛ مطابقة NFKC مع المتصفح لم تستكمل.
- فحص أرصدة الوقود التاريخية على مستوى اليوم أثناء الاستيراد؛ القيد ليس بعد محركاً للعمليات المالية المتزامنة.
- استيراد ذري لنسخة مالك واحدة عند مراجعة محددة، مع مطابقة جميع المصفوفات وترتيبها ومحتواها الأصلي، ورفض إعادة الاستيراد فوق نسخة مرحّلة.
- منع وصول anon و authenticated إلى المخطط الجديد. لا تضفه إلى Supabase exposed schemas. الوظائف بصلاحية المستدعي وليست SECURITY DEFINER.
- `002-smoke-test.sql`: اختبار أولي للترحيل والعزل والصلاحيات والمطابقة، يجري داخل معاملة تنتهي بـ rollback. يتطلب نسخة تجريبية موجودة في قاعدة المصدر.

## طريقة الاختبار
1. جهّز مشروع PostgreSQL/Supabase منفصلاً للاختبار مع المخطط V1 ومالك تجريبي وبيانات صناعية. لا تستخدم قاعدة سوق الأسماك أو قاعدة المرفأ الفعلية.
2. شغّل 001 مرة واحدة بصلاحية مسؤول قاعدة البيانات. إذا فشل التنفيذ تُلغى المعاملة؛ لا تشغل الملف مرة ثانية على مخطط موجود دون مراجعة.
3. شغّل 002 في المشروع التجريبي. يجب أن يظهر PASS ولا تبقى بيانات مستوردة نتيجة الاختبار.
4. جرّب بيانات تالفة عمداً: معرفات مكررة، مراجع مفقودة، رصيد وقود سالب، حالات غير صحيحة. يجب أن يرفض الاستيراد بالكامل؛ لا تحذف السجلات الأصلية لمعالجة الرفض.
5. في اختبار لاحق وبعد نسخة احتياطية مستقلة، استخدم stage_owner مع UUID المالك ورقم المراجعة المعروف، ثم verify_owner. نجاح المطابقة لا يعني أن النسخة ستبقى متزامنة؛ أي تغير في مراجعة المصدر يجعل verify_owner يرفض المقارنة.

## ما لم ينفذ بعد
- لم يتم تشغيل SQL في PostgreSQL فعلياً بعد؛ لا توجد نتيجة اعتماد أو اختبار RLS ميداني.
- هذا المخطط نسخة مرحلية للمالك فقط؛ لم يرحل حسابات الموظفين أو الحسابات الشخصية ولم يضف API كتابة/قراءة للبرنامج.
- الحقول المكتوبة في الأعمدة والعناصر الأصلية محفوظة معاً؛ قبل تفعيل الكتابة يجب اعتماد مصدر حقيقة واحد ومنع التباين بينهما. سجلات التدقيق المستوردة ليست سجل تدقيق مؤسسياً غير قابل للتعديل.
- لم تُعالج الكتابة المتزامنة لكل سجل أو التحقق من صلاحية العمليات المتعددة أو الرصيد تحت التزامن. ستضاف معاملات الخادم، سجل تدقيق من الخادم، صلاحيات تفصيلية، وسياسة نقل تدريجي قابلة للتراجع بعد اختبار الترحيل.
- لا تعديل على واجهات الإصدار الحالي ولا تغيير تلقائي في بيانات المستخدم.
